# System Design Cheat Sheet

## Как пользоваться

Этот cheat sheet создан для подготовки к System Design интервью. Каждый файл — самодостаточный справочник по теме.

**На интервью от вас ждут:**
1. Умение задавать уточняющие вопросы (requirements)
2. Back-of-envelope calculations (оценка нагрузки)
3. High-level design с обоснованием выбора
4. Deep dive в критичные компоненты
5. Обсуждение trade-offs

## Шаблон ответа на любой System Design вопрос

### 1. Уточни требования
```
"Прежде чем начать, хочу уточнить несколько вещей..."
- Сколько пользователей? DAU/MAU?
- Какие операции критичны по latency?
- Нужна ли глобальная доступность?
- Какой бюджет? (иногда спрашивают)
```

### 2. Прикинь цифры
```
Users: 10M DAU
Actions per user: 10/day
Total requests: 100M/day ≈ 1200 RPS (average)
Peak: 3-5x average ≈ 5000 RPS
```

### 3. Нарисуй архитектуру
- Начни с простого: Client → Load Balancer → Service → Database
- Добавляй компоненты по мере обсуждения

### 4. Обоснуй каждый выбор
```
"Я выбираю PostgreSQL, потому что:
1. Нужны транзакции для платежей
2. Данные структурированы
3. Команда уже знает PostgreSQL"
```

## Частые ошибки на интервью

| Ошибка | Как избежать |
|--------|--------------|
| Сразу прыгать в решение | Потрать 5 минут на требования |
| Не считать нагрузку | Всегда делай back-of-envelope |
| Говорить "это сложно" | Объясни почему и предложи упрощение |
| Молчать когда думаешь | Озвучивай мыслительный процесс |
| Защищать свой дизайн | Будь открыт к критике, это диалог |
